# PLAN 08 — i18n: English by default, Indonesian as an option (0.6.0)

Written by `wkr-i18n-plan-01`, 2026-11-27, branch `feature/i18n-en`. Research: `R&D/09-i18n.md` (inventory, bundle
numbers, Bun spike, comparable products). Binding inputs: owner decision 2026-11-27 (English default for the whole
product, Indonesian kept as an option), global Rule 24, `PLAN/DECISIONS.md` B30 (bundle budgets) and B11 (asset
caching), `docs/content-guide.md`.

Status: plan only, nothing built.

## 1. Goals and non-goals

Goals

- G1. Every user-visible text defaults to English: web UI, landing, login, public 404, server text that reaches users
  (Telegram, downloads, OG preview), CLI output, `panel docs` guides.
- G2. Indonesian stays complete and selectable: web (per user, persists), Telegram (per panel), CLI (per shell).
- G3. Bundle budgets hold for English users (B30: `/` ≤ 150 KB, `/panel` initial ≤ 215 KB gzip).
- G4. Keys cannot drift between locales (compile time + one runtime parity test).

Non-goals

- More than two locales, RTL, plural rules beyond what the function leaves already do, translation tooling
  (ICU MessageFormat, i18next, Crowdin). The function-leaf dictionaries already handle grammar; adding a library buys
  nothing for two locales (Rule 10).
- Translating stored data (audit rows, job params, user names).
- Live language switch without reload. Switching is rare; a reload keeps every module-level copy correct (§4.4).

## 2. Locale model

- `type Locale = "en" | "id"`, `DEFAULT_LOCALE = "en"`, `LOCALES = ["en", "id"]`, `parseLocale(v): Locale | null`
  (accepts `en`, `id`, `en-*`, `id-*`, `in` (legacy Java code for Indonesian), case-insensitive). One file:
  `src/shared/locale.ts` (used by web, server and CLI).
- Intl tags: `en → "en-US"`, `id → "id-ID"` (`INTL_TAG` in the same file).

## 3. Detection and persistence

### 3.1 Web (SPA, no SSR)

Order at boot, first valid value wins:

1. `?lang=en|id` in the URL (share links, the switcher on `/` and `/login`). A valid value is saved to localStorage
   and removed from the address bar with `history.replaceState` (Gitea pattern, R&D §5).
2. localStorage `panel-termux:lang` (same storage pattern and try/catch rules as `THEME_STORAGE_KEY`,
   `src/web/theme/theme.preference.ts:8`).
3. `navigator.languages`: first entry whose base is `id` or `en`.
4. `en`.

The signed-in user's server-side preference wins over all of these as soon as it is known: after `GET /api/me`
returns, if `me.locale` is non-null and differs from the active locale, write it to localStorage and reload once
(guard: a `sessionStorage` flag so a broken value cannot loop). localStorage is therefore a cache of the server value
for signed-in users and the only store for visitors.

Server-side store: new nullable column `user.locale` (`null` = follow the device). Migration `drizzle/0009_user_locale.sql`
(`ALTER TABLE user ADD COLUMN locale text;` — nullable, no backfill needed; drizzle's journal makes it run once).
`Me` gains `locale: Locale | null` (`src/shared/me.types.ts`); `PATCH /api/me { locale: "en" | "id" | null }` in
`src/server/routes/me.routes.ts` (validated at the boundary, 400 otherwise, audit action `me.locale`).

### 3.2 Switcher

- Profile page (`src/web/pages/profile.*`): new "Language" card next to the theme card (`profile.theme.tsx` is the
  model): options **English**, **Bahasa Indonesia**, **Follow browser** (= `null`). Saves via PATCH, writes
  localStorage, reloads.
- Landing footer and login page: a compact link "Bahasa Indonesia" / "English" (always written in its own language)
  that navigates to `?lang=<other>`. No account needed.
- Language names are never translated (`English`, `Bahasa Indonesia`), so a user lost in the wrong language finds the
  way back.

### 3.3 `<html lang>`, title, OG

- `src/web/index.html`: `lang="en"`, English `<title>` and description (served as-is for unknown/crawler requests).
- Boot sets `document.documentElement.lang` to the active locale before render. No new inline script, so the CSP
  hashes of the theme script stay valid.
- `src/server/http/seo.ts`: `OG_TEXT` becomes `Record<Locale, …>`. `/` is English by default; `/?lang=id` gets the
  Indonesian OG text, `og:locale` `id_ID`, `<html lang="id">`, and an Indonesian image `og.id.png`. Both variants
  emit `og:locale:alternate` and `<link rel="alternate" hreflang="en|id|x-default">` (canonical stays `/`). This makes
  Indonesian share links preview in Indonesian without SSR. The equality test becomes
  `OG_TEXT.en == tLanding.meta` and `OG_TEXT.id == idLanding.meta`.
- `src/web/assets/og.png` re-rendered in English; the current image moves to `og.id.png`.

### 3.4 Telegram

New setting `alerts.language` (`en` | `id`, default `en`) in `SETTING_KEYS` (`src/shared/dev.types.ts:130-151`),
the server registry (`src/server/settings.registry.ts`) and the web settings registry/copy. Digests, the test
message and the overflow message use it. It is a panel setting, not the viewer's choice, because the chat has no
viewer.

### 3.5 CLI

`cliLocale(env, argv)`: `--lang en|id` → `PANEL_LANG` → `LC_ALL` → `LC_MESSAGES` → `LANG` (POSIX precedence; only a
value starting with `id`/`in` selects Indonesian) → `en`. Termux sets `LANG=en_US.UTF-8` by default, so phones get
English unless the owner sets `PANEL_LANG=id` (documented in `panel -h` and the README). `--lang` is accepted by every
command and listed under general options. `panel doctor --json` keys and ids stay English/stable; only `label`/`hint`
text follows the locale.

## 4. Web architecture

### 4.1 Files

Keep the per-domain split that B30 depends on. For each of the 25 domains:

- `src/web/i18n/en.<domain>.ts` exports `t<Domain>` (e.g. `tShell`, `tSiteDetail`): the English source of truth,
  `as const`, wrapped in `msg("<domain>", {...})` (§4.3). Consumers import only these.
- `src/web/i18n/id.<domain>.ts` keeps today's Indonesian text, exports `id<Domain>` typed
  `: Messages<typeof t<Domain>>`. It may only `import type` from `en.*` (enforced by a test), so it never pulls English
  into the pack or the pack into English chunks.
- `src/web/i18n/id.pack.ts`: `export default { shell: idShell, site: idSite, … } satisfies OverlayPack` — the only
  importer of `id.*` in the web bundle.
- `src/shared/i18n.ts` (shared so `problem.copy` can use it): `Messages<T>`, `msg()`, `applyOverlay()`, overlay registry.
  ≈40 lines.

Naming change for consumers: `import { idShell } from "@/web/i18n/id.shell"` → `import { tShell } from
"@/web/i18n/en.shell"`, `idShell.` → `tShell.`. Mechanical (sed over 164 files + 20 tests).

Composition stays as today: `en.dev.ts` nests `tDevAudit`…, `en.site.ts` imports `tSiteSetup`. Children evaluate (and
are overlaid) before the parent; applying the parent overlay re-writes the same leaves with the same values, so it is
idempotent and `id.dev.ts` may keep nesting `idDevHealth`… exactly as today.

### 4.2 Types (no drift)

```ts
// src/shared/i18n.ts
export type Messages<T> = T extends string
  ? string
  : T extends (...a: infer A) => string
    ? (...a: A) => string
    : T extends readonly (infer U)[]
      ? readonly Messages<U>[]
      : { readonly [K in keyof T]: Messages<T[K]> };
```

`export const idShell: Messages<typeof tShell> = { … }` fails to compile on a missing key, an extra key (excess
property check on the literal), or a function with different parameters. Parameter types flow from English, so
`(n) =>` needs no annotation.

Runtime parity test (`tests/i18n.parity.test.ts`): for every pack entry, same key set at every depth as the English
object, same `typeof` per leaf, same function `length`, no empty strings, every function leaf returns a non-empty
string for a sample call. Plus: no `id.*` imported outside `id.pack.ts`, `id.*` import only types from `en.*`.

### 4.3 Loading (option C from R&D §6.3)

```ts
// src/shared/i18n.ts (sketch)
const overlays: Record<string, unknown> = {};
/** English dictionary, patched in place with the active overlay registered before it evaluates. */
export function msg<T extends object>(domain: string, en: T): T {
  const o = overlays[domain];
  if (o) applyOverlay(en, o); // deep: objects recurse, leaves replaced
  return en;
}
export const setOverlays = (pack: Record<string, unknown>) => Object.assign(overlays, pack);
```

```ts
// src/web/i18n/locale.boot.ts — FIRST import of src/web/main.tsx
export const locale: Locale = detectLocale(); // §3.1 steps 1-4
document.documentElement.lang = locale;
if (locale === "id") setOverlays((await import("./id.pack")).default);
```

- Top-level `await` in the first import delays every later module of the entry and every lazy chunk, so all
  dictionaries (and the 132 module-level aliases/copies) are already Indonesian when they evaluate. Verified in a
  spike (R&D §6.3). Needs `es2022` module output, which Bun already emits; all target browsers support TLA.
- If the pack request fails: catch, log `warn`, continue in English, show a toast "Indonesian could not be loaded"
  (English text, since the pack is what failed). No empty strings.
- English users never request the pack. Indonesian users download ≈36 KB gzip once (cached `immutable`, B11).
- Upgrade path (only if measured slow): split into a core pack (≈10.7 KB) at boot and per-route-group packs awaited in
  the route `lazy` loaders before the page import. Same `msg()` mechanism.

### 4.4 Switching

Save (PATCH or localStorage) → `location.reload()`. No context, no re-render plumbing, no stale module-level copies.

### 4.5 Formatting

- `src/shared/format.id.ts` → `src/shared/format.number.ts`: every function takes `locale: Locale` as its last,
  **required** parameter (the server must always pass one explicitly). Separators per locale: en `1,234.5`,
  id `1.234,5`. Units per locale: en `d`, `h`, `min`, `s` → "7 min 17 s", "1 d 9 h", "0 s"; id unchanged
  (`hari/jam/mnt/dtk`). Stays Intl-free (same reason as today, R&D §4).
- `src/web/shared/format.ts` is the only web entry point and binds the active locale: `formatBytes = (b) =>
  base.formatBytes(b, locale)`, etc. All 7 `toLocale*("id-ID")` calls use `INTL_TAG[locale]`; `formatClock` keeps
  `hour12: false`. `${days} hari` and `inti` move into `tShell.time` / `tShell.load`. `profile.page.tsx:37` and
  `profile.sessions.tsx:30` call a `format.ts` helper instead of Intl directly. `problems.page.tsx:37` (`sv-SE` sort key)
  stays.
- Relative time pieces already live in `idShell.time`; English gets "just now", "3 min ago", "in 5 min", "yesterday",
  "4 days ago".
- `id.job.ts:1` imports `formatBytes` from `@/web/shared/format` instead of the shared module.

## 10. Gates and acceptance

Gates after every wave: `bun run typecheck`, `bun run lint`, `bun test`, `bun run build`, `bun run bundle:check`,
`bun run build:local && sh scripts/cli.test.sh dist/panel`.

Acceptance criteria:

1. A fresh browser with `navigator.languages = ["en-US"]` (and also one with `["de"]`) shows no Indonesian word on
   `/`, `/login`, the public 404, and every `/panel` and `/dev` page (checked by `web.no-indonesian` + a manual pass).
2. `?lang=id` or Profile → Bahasa Indonesia shows the full Indonesian UI, identical to 0.5.1 copy.
3. The choice persists across reloads; a signed-in user's choice follows them to a second browser after sign-in.
4. `<html lang>` matches the active locale; `/` preview is English, `/?lang=id` preview is Indonesian.
5. Key parity test green; `id.*` compiles against `Messages<typeof t*>`.
6. `bundle:check`: `/` ≤ 150 KB, `/panel` initial ≤ 215 KB, and both no more than 1 KB above the wave-0 baseline;
   id pack ≤ 45 KB gzip.
7. Telegram test message arrives in the language of `alerts.language`.
8. `panel -h`, `panel doctor`, `panel docs` print English with a clean env and Indonesian with `PANEL_LANG=id` or
   `--lang id`; `panel docs paket` still works.
9. CHANGELOG lists the breaking changes: default language, CSV header, docs topic rename (alias kept), anchor rename
   (aliases kept).

## 12. Open questions (recommended answers)

1. **Server-side preference or localStorage only?** Recommended: server-side `user.locale` (as asked), because it
   follows the user across devices and lets server-made downloads use it later. Cheaper fallback if the owner wants
   fewer moving parts: localStorage only, like the theme, and drop the migration.
2. **What does "Follow browser" mean for a signed-in user?** Recommended: `user.locale = null`; new users start at
   `null`. The switcher on landing/login never writes the server value.
3. **English time units?** Recommended: `d`, `h`, `min`, `s` ("7 min 17 s", "1 d 9 h"); relative "3 min ago". Alternative
   "1 day 9 h" reads friendlier but needs plural handling in a shared formatter.
4. **Date style for `en`?** Recommended `en-US` with 24-hour clock in logs (`formatClock`) and Intl defaults elsewhere
   ("Nov 26, 2026, 9:26 PM"). Alternative `en-GB` ("26 Nov 2026, 21:26") is closer to today's layout; owner's call.
5. **Screenshots** (`README_ASSETS/*.png` 13, landing `*.webp` 8, `og.png`): need a browser session in English demo
   mode. Recommended: a separate owner-approved task after wave 1; keep Indonesian images as `*.id.*` for `README.id.md`
   and `?lang=id`.
6. **Translate the ecosystem block comments?** Recommended: no, until the block changes for a functional reason (§5).
7. **Installer messages in Indonesian too?** Recommended: no, English only (4 lines, runs before the binary).
8. **Version?** Recommended 0.6.0: user-visible default change plus small breaking changes (CSV header).
