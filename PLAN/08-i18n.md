# PLAN 08 — i18n: English by default, Indonesian as an option (0.6.0)

Written by `wkr-i18n-plan-01`, 2026-11-27, branch `feature/i18n-en`; revised after the debate by `wkr-i18n-plan-02`
the same day. Research: `R&D/09-i18n.md` (inventory, bundle numbers, Bun spike, comparable products). Debate:
`PLAN/debate/08-i18n-debate.md` ("debate n" below = finding n there). Binding inputs: owner decision 2026-11-27
(English default for the whole product, Indonesian kept as an option), global Rule 24, `PLAN/DECISIONS.md` §E (i18n
v0.6.0; wins over this plan on conflict), B30 (bundle budgets), B11 (asset caching), `docs/content-guide.md`.

Status: plan only, nothing built. Revision 2 (after debate).

## 1. Goals and non-goals

Goals

- G1. Every user-visible text defaults to English: web UI, landing, login, public 404, server text that reaches users
  (Telegram, downloads, OG preview), CLI output, `panel docs` guides.
- G2. Indonesian stays complete and selectable: web (per user, persists), Telegram (per panel), CLI (per install).
- G3. Bundle budgets hold for English users (B30: `/` ≤ 150 KB, `/panel` initial ≤ 215 KB gzip), measured on real
  English text (E6).
- G4. Keys cannot drift between locales (compile time + one runtime parity test).
- G5. Upgrading from 0.5.x never silently switches an existing Indonesian setup to English where the panel can tell
  (Telegram via backfill, CLI via the `panel init` question; E11, E12).

Non-goals

- More than two locales, RTL, plural rules beyond what the function leaves already do, translation tooling
  (ICU MessageFormat, i18next, Crowdin). The function-leaf dictionaries already handle grammar; adding a library buys
  nothing for two locales (Rule 10).
- Translating stored data (job params, user names). Exception: stored device labels are normalized on read (§5, E10).
- Live language switch without reload. Switching is rare; a reload keeps every module-level copy correct (§4.4).
- Localized OG previews, `hreflang`, `og.id.png`, locale-aware data-key text (scope cuts, E13).

## 2. Locale model

- `type Locale = "en" | "id"`, `DEFAULT_LOCALE = "en"`, `LOCALES = ["en", "id"]`, `parseLocale(v): Locale | null`
  (accepts `en`, `id`, `en-*`, `id-*`, `in` (legacy Java code for Indonesian), case-insensitive). One file:
  `src/shared/locale.ts` (used by web, server and CLI).
- Intl tags: `en → "en-US"`, `id → "id-ID"` (`INTL_TAG` in the same file).

## 3. Detection and persistence

### 3.1 Web (SPA, no SSR)

Order at boot, first valid value wins:

1. `?lang=en|id` in the URL (the switcher on `/` and `/login`). A valid value is saved to localStorage and removed
   from the address bar with `history.replaceState` (Gitea pattern, R&D §5).
2. localStorage `panel-termux:lang` (same storage pattern and try/catch rules as `THEME_STORAGE_KEY`,
   `src/web/theme/theme.preference.ts:8`).
3. `navigator.languages`: first entry whose base is `id` or `en`.
4. `en`.

Signed-in users (E2, debate 6): when `GET /api/me` returns a non-null `me.locale`, the client writes it to
localStorage — at sign-in completion and on any later `/api/me` load. It does **not** reload; the server value
applies at the next boot. No reload-on-mismatch, no `sessionStorage` guard. localStorage is therefore a cache of the
server value for signed-in users and the only store for visitors. A user who signs in on a second browser sees the
first page in the device language and their own language from the next navigation that reloads (or the next visit);
accepted.

Server-side store (E3, debate 5):

- `user.locale`: nullable text column (`null` = follow the device). Migration `drizzle/0009_user_locale.sql`:
  `ALTER TABLE user ADD COLUMN locale text;` (nullable, no backfill; drizzle's journal runs it once) plus the
  `alerts.language` backfill of §3.4. Regenerate `drizzle/migrations.js` and `drizzle/migrations.d.ts`
  (`bun run db:generate`), update `tests/db.migrate.test.ts` for the 10th embedded migration.
- better-auth: `locale` is an `additionalField` in `src/server/auth/auth.service.ts:31-34` next to `role`:
  `{ type: "string", required: false, input: false }` — clients cannot set it through sign-up/update.
- `Me` gains `locale: Locale | null` (`src/shared/me.types.ts`); `PATCH /api/me { locale: "en" | "id" | null }` in
  `src/server/routes/me.routes.ts` (validated at the boundary with `parseLocale`, 400 otherwise, audit action
  `me.locale`). It is the only writer.

### 3.2 Switcher

- Profile page (`src/web/pages/profile.*`): new "Language" card next to the theme card (`profile.theme.tsx` is the
  model): options **English**, **Bahasa Indonesia**, **Follow browser** (= `null`). Saves via PATCH, writes
  localStorage (or removes it for `null`), reloads. This user-initiated reload is the only reload.
- Landing footer and login page: a compact link "Bahasa Indonesia" / "English" (always written in its own language)
  that navigates to `?lang=<other>`. No account needed; it never writes the server value.
- Language names are never translated (`English`, `Bahasa Indonesia`), so a user lost in the wrong language finds the
  way back.

### 3.3 `<html lang>`, title, OG

- `src/web/index.html`: `lang="en"`, English `<title>` and description (served as-is for unknown/crawler requests).
- The bootstrap sets `document.documentElement.lang` to the active locale before mount. No new inline script, so the
  CSP hashes of the theme script stay valid.
- `src/server/http/seo.ts`: `OG_TEXT` becomes English only; `og:locale` `en_US`. The equality test becomes
  `OG_TEXT == tLanding.meta`. No `?lang=id` variant, no `og:locale:alternate`, no `hreflang`, no `og.id.png` (E13).
- `src/web/assets/og.png` is re-rendered in English with the screenshots in wave 2 (E15).

### 3.4 Telegram

New setting `alerts.language` (`en` | `id`, default `en`) in `SETTING_KEYS` (`src/shared/dev.types.ts:127-151`),
the server registry (`src/server/settings.registry.ts`) and the web settings registry/copy. Digests, the test
message and the overflow message use it. It is a panel setting, not the viewer's choice, because the chat has no
viewer.

Upgrade backfill (E11, debate 8): migration 0009 inserts `alerts.language = id` when alerts were configured before
0.6.0, idempotently:

```sql
-- 0.5.x sent Telegram text in Indonesian; keep it for panels that already had alerts set up (PLAN/08 §3.4).
INSERT OR IGNORE INTO setting (key, value)
SELECT 'alerts.language', '<"id" encoded as the settings registry stores values>'
WHERE EXISTS (SELECT 1 FROM setting WHERE key IN ('alerts.telegram_bot_token', 'alerts.telegram_chat_id'));
```

The worker checks the stored value encoding in `settings.queries` before writing the literal and covers both cases
(configured → `id`, fresh → no row → default `en`) in a migration test.

### 3.5 CLI

`cliLocale(env, argv, envFile)` (E12, debate 9): `--lang en|id` → `PANEL_LANG` from the process env →
`PANEL_LANG` from the panel env file (`~/.panel/.env`, read with `readEnvFile`, `src/cli/env.file.ts`) → `LC_ALL` →
`LC_MESSAGES` → `LANG` (POSIX precedence; only a value starting with `id`/`in` selects Indonesian) → `en`.

Why the env file matters: Termux does not see the Android locale. Checked on POCO (read-only, 2026-11-27): the phone's
`persist.sys.locale` is `id-ID`, yet the Termux login shell has `LANG=en_US.UTF-8` (`LC_ALL` empty) and a clean
`env -i sh` has no `LANG`. Env-based detection alone would always pick English.

- `panel init` asks once, before any other step: `Language / Bahasa: 1) English 2) Bahasa Indonesia` (default 1).
  Skipped when `--lang` or `PANEL_LANG` is set, when the env file already has `PANEL_LANG`, or when non-interactive
  (`--yes`, no TTY). The answer is written as `PANEL_LANG=en|id` to the panel env file and used for the rest of the
  run.
- `PANEL_LANG` becomes an optional entry in `ENV_VARS` (`src/shared/env.schema.ts`), validated with `parseLocale`.
  Consequences: `panel env` lists and edits it, the `.env` template documents it, and `childEnv`
  (`src/cli/cli.host.ts:162-171`) and the server's child scrubber (`src/server/main.ts:13`) remove it from site
  processes — the panel's language is not the sites' business. The server itself ignores it.
- `--lang` is accepted by every command and listed under general options. `panel doctor --json` keys and ids stay
  English/stable; only `label`/`hint` text follows the locale.

## 4. Web architecture

### 4.1 Files

Keep the per-domain split that B30 depends on. For each of the 25 domains:

- `src/web/i18n/en.<domain>.ts` exports `t<Domain>` (e.g. `tShell`, `tSiteDetail`): the English source of truth,
  `as const`, wrapped in `msg("<domain>", {...})` (§4.3). Consumers import only these.
- `src/web/i18n/id.<domain>.ts` keeps today's Indonesian text, exports `id<Domain>` typed
  `: Messages<typeof t<Domain>>`. It may only `import type` from `en.*` (enforced by a test), so it never pulls English
  into the pack or the pack into English chunks.
- `src/web/i18n/id.pack.ts`: `export default { shell: idShell, site: idSite, … } satisfies OverlayPack` — the only
  importer of `id.*` in the web bundle.
- `src/shared/i18n.ts` (shared so `problem.copy` can use it): `Messages<T>`, `OverlayPack`, `msg()`,
  `applyOverlay()`, overlay registry. ≈50 lines. **Imports no dictionary** (E5).
- `src/web/i18n/locale.detect.ts`: `detectLocale()` (§3.1 steps 1-4) and the localStorage helpers.
- `src/web/main.tsx`: the bootstrap (§4.3). `src/web/app.mount.tsx`: today's `main.tsx` body (`createRoot`, router,
  providers) as `export function mount()`.

Naming change for consumers: `import { idShell } from "@/web/i18n/id.shell"` → `import { tShell } from
"@/web/i18n/en.shell"`, `idShell.` → `tShell.`, done by `scripts/codemod-i18n.ts` (§9, E7). It also rewrites
type-position uses: `keyof typeof idShell.groups` (`src/web/layout/nav.items.ts:42`), `typeof
idLanding.shots.items` (`src/web/landing/landing.shots.ts:12`) and any other `typeof id<Domain>` the script finds.

Composition stays as today: `en.dev.ts` nests `tDevAudit`…, `en.site.ts` imports `tSiteSetup`. Children evaluate (and
are overlaid) before the parent; applying the parent overlay re-writes the same leaves with the same values, so it is
idempotent and `id.dev.ts` may keep nesting `idDevHealth`… exactly as today.

### 4.2 Types (no drift)

```ts
// src/shared/i18n.ts
export type Messages<T> = T extends string
  ? string
  : T extends (...a: infer A) => string
    ? (...a: A) => string
    : T extends readonly (infer U)[]
      ? readonly Messages<U>[]
      : { readonly [K in keyof T]: Messages<T[K]> };

/** Domain name → English dictionary type; one entry per `msg()` domain. */
export type Domains = { shell: typeof tShell; site: typeof tSite /* … */ }; // type-only imports
export type OverlayPack = { [K in keyof Domains]: Messages<Domains[K]> };
```

(`Domains` uses `import type` only, so `i18n.ts` stays free of runtime dictionary imports; if the type imports make
the shared module awkward, `Domains`/`OverlayPack` live in `src/web/i18n/id.pack.types.ts` instead — base worker's
call.)

`export const idShell: Messages<typeof tShell> = { … }` fails to compile on a missing key, an extra key (excess
property check on the literal), or a function with different parameters. Parameter types flow from English, so
`(n) =>` needs no annotation. Arrays: `Messages` cannot check length, so the runtime test does (below).

**tsc spike first** (debate 10): before the codemod, type `id.job.ts` (102 function leaves) against a hand-made
`en.job.ts` copy and record `tsc --extendedDiagnostics` check time and one deliberate error message in the wave-0a
report. If check time grows by more than ≈2 s or errors are unreadable, stop and report before continuing.

Runtime parity test (`tests/i18n.parity.test.ts`): for every pack entry, against the English object: same key set at
every depth, same `typeof` per leaf, **same array length**, same function `length`, no empty strings; every function
leaf is called with sample arguments guessed per parameter (try `1`, `"x"`, `new Date(0)` until one call returns) and
must return a non-empty string. Plus: no `id.*` imported outside `id.pack.ts`; `id.*` import only types from `en.*`;
`src/shared/i18n.ts` imports no `en.*`/`id.*` at runtime.

### 4.3 Loading (dynamic-import boundary, E5, debate 1)

The first draft used top-level `await` in the first import of `main.tsx`. Under `splitting: true` that does not hold:
a dictionary in a shared chunk is a static import of the entry chunk and evaluates before the entry body's `await`
(reproduced on Bun 1.4.2; correction note in R&D 09 §6.3). The boundary is now a dynamic import of the whole app:

```ts
// src/shared/i18n.ts (sketch)
const overlays: Record<string, unknown> = {};
/** English dictionary, patched in place with the active overlay registered before it evaluates. */
export function msg<T extends object>(domain: string, en: T): T {
  const o = overlays[domain];
  if (o) applyOverlay(en, o); // objects recurse; leaves and arrays replaced wholesale
  return en;
}
export const setOverlays = (pack: Record<string, unknown>) => Object.assign(overlays, pack);
```

```ts
// src/web/main.tsx — the whole file (~10 lines); imports nothing that touches a dictionary
import { setOverlays } from "@/shared/i18n";
import { detectLocale } from "./i18n/locale.detect";

const locale = detectLocale();
document.documentElement.lang = locale;
if (locale === "id") setOverlays((await import("./i18n/id.pack")).default); // failure handling below
const { mount } = await import("./app.mount");
mount();
```

- Every module that reads a dictionary (router, layout, providers, pages, components, `format.ts`) is reachable only
  through `app.mount`, so nothing evaluates a dictionary before the overlay is registered, whatever chunk it lands in.
- If the pack request fails: catch, log `warn` (operation + cause), set `lang="en"`, mount in English, and show a toast
  "Indonesian could not be loaded" (English text, since the pack is what failed). No empty strings.
- English users never request the pack. Indonesian users download ≈36 KB gzip once (cached `immutable`, B11).
- Cost for English users: one extra chunk hop (entry → `app.mount` chunk). Bun emits the static imports of the mount
  chunk as preloadable; the base worker measures first render on `/` and `/panel` before/after (local build, throttled
  "Fast 3G" profile or tunnel timing on POCO) and reports the delta. Expected: a few ms, since the entry becomes tiny.
- `scripts/bundle-report.ts`: an entry group is now "bootstrap entry + `app.mount` chunk + their static imports"; `/`
  and `/panel` initial sums use that group. Budgets unchanged (`/` ≤ 150 KB, `/panel` ≤ 215 KB gzip). Leak check: no
  `id.*` module in any chunk except the pack chunk. New row "id pack (lazy)" with soft budget 45 KB.
- Upgrade path (only if measured slow): split into a core pack (≈10.7 KB) at boot and per-route-group packs awaited in
  the route `lazy` loaders before the page import. Same `msg()` mechanism.

Behavioral boot test (`tests/i18n.boot.test.ts`, replaces the import-order test): `Bun.build` the real
`src/web/index.html` entry with the production config (`splitting: true`, minify) into a temp dir, stub
`document`/`localStorage`/`navigator` with `panel-termux:lang = id`, load the built entry, and assert that a
module-level alias is Indonesian — `SITE_ANCHORS[0].label` (`src/web/site/site.anchors.tsx:9`) plus one value from a
dictionary that lands in a **shared** chunk (`tShell`/`tCommon`, the blocker case). Second case with `lang = en`:
English values and the pack chunk never requested. The mechanism for observing the values (e.g. a build plugin that
swaps `app.mount` for a probe module importing those modules and writing to `globalThis`) is the base worker's call,
as long as the real bootstrap, real `id.pack`, real splitting config and real chunk layout are built; no test hook in
production code.

### 4.4 Switching

Save (PATCH or localStorage) → `location.reload()`. No context, no re-render plumbing, no stale module-level copies.

### 4.5 Formatting

- `src/shared/format.id.ts` → `src/shared/format.number.ts`: every function takes `locale: Locale` as its last,
  **required** parameter (the server must always pass one explicitly). Separators per locale: en `1,234.5`,
  id `1.234,5`. Units per locale: en `d`, `h`, `min`, `s` → "7 min 17 s", "1 d 9 h", "0 s"; id unchanged
  (`hari/jam/mnt/dtk`). Stays Intl-free (R&D §4: the server builds Telegram text without depending on runtime ICU
  data, and web/server output stays byte-equal).
- `src/web/shared/format.ts` is the only web entry point and binds the active locale: `formatBytes = (b) =>
  base.formatBytes(b, locale)`, etc. All 7 `toLocale*("id-ID")` calls use `INTL_TAG[locale]`. English is `en-US` with
  a 24-hour clock: `hourCycle: "h23"` in `formatClock` **and** `formatDateTime` (E4; `hour12: false` alone renders
  "24:05" in some engines). `${days} hari` and `inti` move into `tShell.time` / `tShell.load`. `profile.page.tsx:37`
  and `profile.sessions.tsx:30` call a `format.ts` helper instead of Intl directly. `problems.page.tsx:37` (`sv-SE` sort
  key) stays.
- Required tests: clock and date-time at 00:05 (`"00:05"`, not `"24:05"`/`"12:05 AM"`); durations `0 s`, `59 s`,
  `1 min`, `7 min 17 s`, `1 d 9 h` and their id equivalents.
- Relative time pieces already live in `idShell.time`; English gets "just now", "3 min ago", "in 5 min", "yesterday",
  "4 days ago".
- `id.job.ts:1` imports `formatBytes` from `@/web/shared/format` instead of the shared module.
- Server: `alert.messages.ts` uses only `format.number.ts` with an explicit locale, never `Intl`/`toLocale*` (checked
  by a test grep in `alert.engine.test.ts`).

## 10. Gates and acceptance

Gates after every wave: `bun run typecheck`, `bun run lint`, `bun test`, `bun run build`, `bun run bundle:check`,
`bun run build:local && sh scripts/cli.test.sh dist/panel`.

Acceptance criteria:

1. A fresh browser with `navigator.languages = ["en-US"]` (and also one with `["de"]`) shows no Indonesian word on
   `/`, `/login`, the public 404, and every `/panel` and `/dev` page (checked by `web.no-indonesian` + a manual pass).
2. `?lang=id` or Profile → Bahasa Indonesia shows the full Indonesian UI, identical to 0.5.1 copy; the built-output
   boot test proves the overlay reaches shared-chunk dictionaries.
3. The choice persists across reloads; a signed-in user's choice reaches a second browser at the next boot after
   sign-in (no reload loop).
4. `<html lang>` matches the active locale; the `/` preview is English.
5. Key parity test green (incl. array lengths); `id.*` compiles against `Messages<typeof t*>`.
6. `bundle:check` after wave 1 (real English): `/` ≤ 150 KB, `/panel` initial ≤ 215 KB, both no more than 1 KB above
   the 0.5.1 baseline; id pack ≤ 45 KB gzip; mount-hop delta reported.
7. Telegram test message arrives in the language of `alerts.language`; a 0.5.x DB with Telegram configured upgrades
   to `alerts.language = id`.
8. `panel -h`, `panel doctor`, `panel docs` print English with a clean env and Indonesian with `PANEL_LANG=id`,
   `--lang id`, or `PANEL_LANG=id` in the panel env file; `panel init` asks once and remembers; `panel docs paket`
   still works.
9. Old audit rows ("Chrome di Android", "Perangkat tidak dikenal") render in English.
10. CHANGELOG lists the breaking changes (E14): default language for web and CLI (`PANEL_LANG=id` to keep
    Indonesian), CSV header, docs topic rename (alias kept), anchor rename (aliases kept), `?akun=dihapus` →
    `?account=deleted` (both accepted).

## 11. Risks

| Risk                                                                                 | Mitigation                                                                                                                  |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| A dictionary evaluates before the overlay (shared chunk, future Bun chunking change) | dynamic-import boundary (§4.3) + behavioral built-output test asserting a shared-chunk dictionary and a module-level alias  |
| A dictionary import creeps into the bootstrap or the registry                        | parity test: `i18n.ts` imports no dictionary at runtime; boot test fails if the shared-chunk value stays English            |
| Extra chunk hop slows first render for English users                                 | measured in wave 0a; the entry shrinks to the bootstrap, so the hop is expected to be small                                 |
| Overlay mutation leaks across test files                                             | tests never call `setOverlays` (§8)                                                                                         |
| 36 KB pack slows first load for Indonesian users on a weak tunnel                    | cached immutable after first visit; core/route split (§4.3) if measured > 1 s extra                                         |
| `Messages<T>` slow or unreadable on large function-leaf files                        | tsc spike on `id.job.ts` before the codemod (§4.2)                                                                          |
| Machine-translated, stiff English                                                    | glossary + review worker + README glosses as the reference                                                                  |
| Upgrade flips an Indonesian owner to English                                         | `alerts.language` backfill; `panel init` asks; CHANGELOG names `PANEL_LANG=id`                                              |
| Old audit rows show "Chrome di Android"                                              | normalized on read (§5)                                                                                                     |
| Scripts parsing the old Indonesian CSV header                                        | CHANGELOG breaking note                                                                                                     |
| Bookmarks to `#persiapan`, `#cadangan`, `?akun=dihapus`                              | alias map / both query forms accepted for 0.6.x                                                                             |
| Codemod touches ≈184 files → merge conflicts with parallel feature work              | committed re-runnable `scripts/codemod-i18n.ts` as a pure rename commit; re-run after rebase instead of resolving conflicts |
