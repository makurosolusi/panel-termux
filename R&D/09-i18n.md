# R&D 09 — i18n: English by default, Indonesian as an option

Written by `wkr-i18n-plan-01`, 2026-11-27, branch `feature/i18n-en` (from `main` @ `63bf820`, v0.5.1). Sources: repo
code (file:line below), `bun run bundle:check`, throwaway measurement scripts and a Bun bundler spike in the session
scratchpad (Bun 1.4.2), and four public sources read with WebFetch (§5). No POCO access, no Docker.

Owner decision (2026-11-27): English is the default language of the whole product (web UI, landing, server-generated
user text, CLI output, `panel docs` guides). Indonesian stays as a selectable option. Global Rule 24 says the same:
default locale `en`, other languages only as additional locales.

## 1. Summary

- The web UI is already 100% dictionary-driven: 25 files in `src/web/i18n/`, **1,702 string leaves + 381 function
  leaves** (≈2,083 entries, ≈62.5 K characters of copy). Outside the dictionaries the web has **no** Indonesian UI
  literals (only URL anchor ids, §3.3).
- The dictionaries are plain `as const` objects imported statically by **164 files** (214 import sites). There is no
  `t()` function, no locale state, no React context. Every read is `idShell.nav.overview`-style.
- Indonesian also lives outside the web dictionaries: `src/shared/problem.copy.ts` (Ringkasan + Telegram), shared
  number/duration formatting with Indonesian separators and units, ~8 server call sites (Telegram text, data-key file,
  audit CSV header, SEO/OG text, user-agent label), and the **entire CLI** (≈340 Indonesian lines inline in 29 files,
  no dictionary) plus the 4 `docs/cli/*.md` guides (238 lines).
- Formatting hard-codes `id-ID` in 7 `toLocale*` calls and hand-rolls Indonesian separators in `src/shared/format.id.ts`
  (deliberately Intl-free so server and web agree byte for byte).
- Bundle: shipping both locales statically puts `/panel` initial at ≈216.6 KB gzip, **over** the 215 KB budget (B30).
  Lazy-loading Indonesian as one pack costs English users 0 bytes and Indonesian users one cached ≈36 KB gzip request.
  A spike confirmed Bun's splitting bundler honours a top-level `await` in the first import of the entry, which makes
  "load the active locale before any UI module evaluates" possible with almost no consumer changes (§6.3). Corrected
  by debate 08: shared chunks escape that `await`; the plan uses a dynamic import of the app instead (§6.3 note).
- 51 of 131 test files assert Indonesian copy (≈288 lines).

## 5. How comparable products pick the language

| Product                                    | Order                                                                                                                                                  | Source                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| **Gitea** (self-hosted panel)              | `?lang=` query (valid → also saved to the `lang` cookie) → `lang` cookie → `Accept-Language` → first locale                                            | `modules/web/middleware/locale.go` (read 2026-11-27); signed-in users also have a language in settings |
| **Grafana**                                | user preference → team → org → server `default_language`; most specific wins                                                                           | grafana.com docs "organization preferences" (read 2026-11-27); browser fallback not documented there   |
| **GitHub Docs**                            | URL path prefix (`/en/`, `/ja/`) decides the page; `user_language` cookie → `Accept-Language` (top 2-3 preferences, base code match) decides redirects | `github/docs` `src/languages/middleware/detect-language.ts` (read 2026-11-27)                          |
| **Cockpit** (web console)                  | translations loaded before boot; `document.documentElement.lang` set from the loaded catalog; English key as fallback                                  | `cockpit-project/cockpit` `pkg/static/login.js` (read 2026-11-27, partial file)                        |
| **github.com, Vercel, Coolify dashboards** | English only, no language setting                                                                                                                      | from memory, **not verified**                                                                          |

Takeaways: (1) an explicit per-user choice beats the browser; (2) the browser language is only a first-visit guess;
(3) a URL parameter is the tool for shareable links, not the main state (Gitea persists it, GitHub Docs uses paths
because docs are crawled per language); (4) mature tools load the catalog **before** first render and fall back to the
English key, never to an empty string.

## 6. Bundle impact

Baseline today (`bun run bundle:check`, 2026-11-27): entry `/` **138.2 KB** gzip (budget 150), `/panel` initial
**205.9 KB** (budget 215, DECISIONS B30), login 15.0 KB lazy, app 51.3 KB lazy.

Dictionary weight (metafile `bytesInOutput` of `src/web/i18n/*`, plus each dictionary minified and gzipped):

| Set                                                                                 | Minified |        gzip (standalone) |
| ----------------------------------------------------------------------------------- | -------: | -----------------------: |
| Entry dictionaries (app, common, shell, session, landing)                           |  15.4 KB |                  ≈6.7 KB |
| `/panel` initial dictionaries (entry + status, history, dev.setup, overview, panel) |  28.6 KB | **10.7 KB** (one bundle) |
| All 25 dictionaries as one module                                                   |   114 KB |              **36.2 KB** |

### 6.1 Option A — both locales bundled statically

`/panel` initial ≈ 205.9 + 10.7 ≈ **216.6 KB → over 215**. Entry ≈ 145 KB (fits, but eats most of the remaining
12 KB). English copy is usually a little shorter than Indonesian, which does not change the verdict. Also doubles
every lazy chunk's copy for users who never switch. Rejected.

### 6.2 Option B — English static, Indonesian lazy per domain

Each route group loads its `id.*` chunk before its page. Smallest download for Indonesian users, but the loader must
finish **before** the page module evaluates (module-level copies, §2), so the fetches serialize (dictionary, then
page) on every first visit of a group. More wiring: one loader per route group, and dictionaries used across groups
(`id.site.setup` by site + CLI, `id.dev.setup` by the overview) need a home.

### 6.3 Option C — English static, Indonesian as one lazy pack loaded at boot (recommended)

- English users: **+0 KB** on `/` and `/panel` (plus a few hundred bytes of loader code).
- Indonesian users: one extra request of ≈36 KB gzip before first render, cached `immutable` (B11) after the first
  visit. Over the Cloudflare tunnel this is one round trip plus ≈36 KB; acceptable for a language the user picked.
- **Spike (Bun 1.4.2, `splitting: true`, `minify: true`)**: an entry whose first import is a module with
  `if (lang === "id") applyOverlay((await import("./id.pack")).default)` evaluates every later module (including
  module-level string copies in the entry and in lazy chunks) **after** the overlay is applied. With `lang = "en"`
  the pack chunk is emitted but never requested, and no other chunk contains the Indonesian strings. This lets the
  English dictionary objects be patched in place, so the 164 consumer files keep their static, typed property reads.
- Upgrade path if 36 KB proves slow on real phones: split the pack into "core" (≈10.7 KB, entry + `/panel` initial)
  at boot and the rest per route group (option B) — the overlay mechanism stays the same.

> **Correction (2026-11-27, debate 08 finding 1).** The spike above is incomplete. With `splitting: true`, a
> dictionary that lands in a **shared** chunk (e.g. `shell`/`common`, imported by the entry and by lazy routes) is a
> static import of the entry chunk and evaluates **before** the entry body's top-level `await`, so the overlay never
> reaches it. Reproduced on Bun 1.4.2. The spike only had dictionaries inside the entry chunk itself. Option C stays,
> but the boundary is a dynamic import of the whole app: `main.tsx` detects the locale, awaits the pack if `id`, then
> `await import("./app.mount")`; nothing that touches a dictionary is statically reachable from the entry. See
> `PLAN/08-i18n.md` §4.3 and `PLAN/DECISIONS.md` E5.

## 8. Open findings for the plan

1. The audit log stores `"Chrome di Android"` at write time (`api.handler.ts:153`), so old rows stay Indonesian
   whatever the fix.
2. Changing the ecosystem block comments forces `BLOCK_VERSION` 2 and a Fix on every installed phone; not worth it for
   comments.
3. `RESET_CONFIRM = "hapus"` is checked on the server; a localized confirm word needs the server to accept the word of
   the requesting locale (or a locale-neutral word).
4. Screenshots (README, landing, `og.png`) need retaking in English; that needs a browser session, which global Rule 1
   reserves for an explicit owner request.
