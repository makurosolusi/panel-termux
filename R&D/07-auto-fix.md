## 2. Inventaris: semua tempat pengguna disuruh mengerjakan hal teknis sendiri

Kolom **Panel bisa?**: **ya** = panel bisa mengerjakannya penuh dengan aman; **sebagian** = panel mengerjakan semua
kecuali satu bagian yang hanya dimiliki pengguna (rahasia, login akun, aplikasi Android, komputer untuk build);
**tidak** = tidak bisa atau tidak boleh (alasan disebut). **P** = prioritas usulan (P0 kartu Persiapan di tangkapan
layar, P1 sering ditemui / murah, P2 jarang / butuh keputusan pemilik). Baris yang berisi teks yang sama di beberapa
file digabung jadi satu item (semua lokasi disebut).

Prinsip yang diambil:

1. **Default = panel mengerjakan.** Tombol aksi di samping masalah, bukan instruksi. Instruksi manual tetap ada tetapi
   dilipat di bawah "Cara manual (untuk pengguna teknis)".
2. **Sebelum mengubah: pratinjau.** Kalimat awam dulu ("Aplikasi yang sudah ada tidak diubah"), diff untuk yang ingin
   melihat.
3. **Selalu bisa dibatalkan.** Backup bertanggal, validasi otomatis, kembali otomatis bila validasi gagal,
   **Batalkan perubahan** setelahnya.
4. **Ubah file ≠ restart.** Perubahan yang memutus layanan butuh persetujuan terpisah dengan konsekuensi nyata (nama app
   yang terputus).
5. **Cek ulang otomatis** setelah aksi, hasil dalam toast + status baris berubah.
6. **Bila tidak bisa** (file aneh, butuh login), katakan kenapa dengan bahasa awam dan buka "Cara manual".

## 4. Temuan teknis untuk desain

- **pm2 membaca ecosystem hanya saat pm2-runtime start** (runit start/restart, reboot) dan saat `pm2 start <eco> --only
  <app>` (deploy pertama situs panel, `deploy.restart.ts`). Mengubah file **tidak** memengaruhi app yang berjalan;
  makuro-solusi dan adminneo tidak dimulai ulang. Konsisten dengan copy lama "pm2 tidak perlu dimulai ulang".
- **runsv membaca `run` hanya saat menyalakan proses.** Menulis `--no-auto-exit` berlaku pada start berikutnya. Panel
  bisa tahu apakah flag sudah aktif dengan membaca `/proc/<pid>/cmdline` pid layanan `pm2` (uid sama; run script sendiri
  membaca `/proc/*/status`).
- **Masih perlu `--no-auto-exit` walau ada penjaga?** Ya (lab E4/E10c): penjaga hanya ada bila ecosystem tidak punya app
  lain, dan tanpa flag pm2-runtime keluar ±8 dtk setelah 0 app online, mis. pemilik menekan **Hentikan** pada semua
  aplikasi. runsv lalu menyalakan ulang dan semua app hidup lagi, jadi "Hentikan" tampak gagal. Flag murah dan aman.
  Prioritasnya tetap warning, tidak memblokir `ready`.
- **Mode file**: ecosystem POCO 0600, `writeAtomic` default 0644. Patcher wajib mempertahankan mode asli (`stat`).
- **Kandidat harus `*.config.js`** (lab E7, `ecosystem.probe.ts:18`) dan berada di folder yang sama (`require('./apps.json')`,
  `__dirname`). `tempPathFor` sekarang menghasilkan `.ecosystem.config.js.panel-tmp`, nama yang ditolak probe.
- **Symlink**: bila ecosystem symlink, tulis ke `realpath` agar link tidak tergantikan file biasa.
- **Penyunting bersamaan**: pemilik bisa sedang membuka `nano`. Hash sebelum/sesudah dicek tepat sebelum `rename`.
- **Duplikasi nama**: blok menambahkan entri `apps.json` hanya bila nama belum ada di daftar tangan (nama situs panel
  sudah ditolak bila bentrok, `name_taken`), jadi pm2 tidak menerima nama ganda.
- **DNS tanpa token**: `cloudflared tunnel route dns <tunnel> <host>` memakai `cert.pem`; hanya membuat (opsi
  overwrite ada), tidak menghapus **(perilaku flag perlu verifikasi pada cloudflared terpasang)**.
- **Fake mode** sekarang menyalin template yang sudah benar (`system.fake.ts:55-74`), jadi QA tidak pernah melihat kartu
  Persiapan gagal. Perlu skenario POCO.
